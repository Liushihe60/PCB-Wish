# 设计执行（Design Engine）

## 前置检查（缺一即停，不空转）

1. `projects/<项目>/MISSION.md` 存在，且 `mission_check.py --json` 为 ok:true。否则提示先运行 intake。**MISSION.md 的交付物清单是"本项目要不要随附教学讲义"的唯一开关**：清单里勾了"教学讲义"，则 **G6 之后必须执行 G7 讲义门**（见下表）；**没勾也要在最终交付说明里写一句"本次不含教学讲义及原因"**（不得默认省略而不说明）。
2. EDA 驱动通道可用：嘉立创EDA专业版桌面客户端 V4.1.60+（`lceda-pro doctor` 或已挂载的 lceda MCP 工具）。不可用 → 输出安装指引并停止。
3. `doctor.py` 的 EDA 级依赖无 FAIL。

## 流程与门禁（G0-G6，门不过不前进）

| 门 | 内容 | 判据（全部确定性，不许凭感觉） |
|---|---|---|
| G0 方案确认 | 功能块树 + 每块的复用来源（blocks/ 里的 verified 块优先；新块须声明来源证据）+ 选型方向 + 层叠建议 | 用户确认（AskUserQuestion）后才进入 IR |
| G0.5 选型定稿 | 库内选型与放置**解耦**（D005，flexiheal-v1 实测教训）：逐件在嘉立创库内搜索（单词关键词、一次一件、批间 ≥6s 防限流）→ 严格匹配（值/封装 token 同现）→ 产出 `spec/bom.json`（位号→确切库器件 UUID/型号/封装）→ BOM 表交用户过目后冻结；未匹配项列出待人工定，**禁止宽松回退**（垃圾匹配污染 BOM） | `bom_finalize.py` 退出码 0 + 用户确认 BOM 表 |
| G1 IR 门 | 写 `spec/ir.json`（结构见 scripts/ir/ir_schema.json）→ 运行 `python "${CLAUDE_PLUGIN_ROOT}/scripts/ir/ir2assert.py" --ir spec/ir.json --out spec/assertions.json` 生成断言文件（断言与 IR 同源，禁止手抄） | `ir_validate.py` PASS + 断言文件已生成 |
| G2 原理图门 | 建库（Symbol/Footprint/Device，pin↔pad 映射逐脚回读）→ 原理图（**放置走 `sch_place_from_bom.py --from-bom spec/bom.json` 零搜索纯机械**；泛型阻容=系统库泛型器件+值属性；连线=GND/电源类 createNetFlag('Ground'/'Power', 网络名)，信号类短距 net port（大规模 net port 有静默并网风险，pitfalls #1，放置后逐页断言）→ ERC | ERC 0 错误 + `netlist_assert.py`（must_connect/net_members 全绿；网表导出须在布线后——无连线时网表校验抛错属预期） |
| G3 PCB 规划门 | 板框、层叠、功能分区摆放图 | 用户确认 |
| G4 布局门 | 按块布局约束（flow/attach/pair）摆放 | 布局 lint：无重叠、**丝印间隙双口径（gap0=0 对 + 装配间隙无零深度相切，见驱动纪律 #7）**、**位号文本不得落在自身器件的丝印轮廓内、不得压任何焊盘、彼此互不重叠（见驱动纪律 #7 ①）**、飞线可布性估算（对齐 pcb-skill"可布线性而非合法性"）+ **朝向可布性闸门（见驱动纪律 #12）** |
| G5 布线门 | 布线（短线内置规则，稠密网络外挂 Freerouting）→ 铺铜 | DRC 0 错误 + 0 未布飞线（铺铜后复测一次） + **过孔↔焊盘净距体检（见驱动纪律 #15）** |
| **G5.5 清零门** | **交付前把本阶段产生的 error 与 warning 全部清零**（见驱动纪律 #13）：ERC/DRC/断言/几何检查/脚本日志里的每一条 error 与 warning 逐条列出 → 能修的当场修完并复测 → 确实修不掉的写**正式豁免记录**（根因 + 影响评估 + 处置建议 + 后续动作） | **error 计数 = 0**；**warning 计数 = 0，或每条都有豁免记录**；豁免记录落 `reports/waivers_*.md`，并由主 session 裁决后才算过门 |
| G6 制造门 | Gerber/钻孔/坐标/BOM 导出 → 独立复核 → DFM | Gerber 独立解析复推参数一致 + 官方 DFM 扩展检查通过 + 冷重启复测 DRC 仍 0 + **G5.5 的豁免记录随交付物一并附上** |
| **G7 讲义门** | **教学讲义（LaTeX→PDF）**：MISSION.md 勾选了就必须做（蓝图 → 逐模块五段式成稿 → 质检+事实性回链 → xelatex 编译 → 逐页渲染评审）。规范见 `skills/teaching-lecture/SKILL.md` | `tex_quality_check.py` 零告警 + **每个数值/公式可回链到决策日志/验证记录/计算书** + 图全部来自真实工程产物 + xelatex×2 编译成功 + 逐页渲染评审通过 |

每个门的产物与证据落盘 `reports/`，作为讲义素材与可追溯记录。

## 门禁登记（G0-G6 每门必做，机械强制）

判据全绿后用门禁状态机登记（前置门不过会拒绝；证据文件不存在会拒绝）：

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/gate.py" --project <项目slug> pass <GATE> \
  --evidence reports/<证据文件> --evidence spec/<证据文件> --note "<一句话>"
python "${CLAUDE_PLUGIN_ROOT}/scripts/gate.py" --project <项目slug> status   # 查看全表
```

- 状态文件 `reports/gates.json` 是唯一事实来源，**禁止手改**（家 hook 会拦下手改，必须走 gate.py）；
- 判据没全绿不许 `pass`——hook 会在你调用 EDA 写操作时拦下未过门的操作，"门不过不前进"由此成为机械规则；
- 某 gate 判 FAIL 用 `gate.py fail <GATE> --reason ...`，其后各门自动回退 pending。

**分工**：G0.5 选型派发专用 agent `pcb-sourcing`（开放网络搜索、数据手册抓取、库内严格搜索与商城网页引用，无画布工具）；G2-G6 执行派 `pcb-design`；验收派只读的 `pcb-verify`。选型外部证据：自由网络搜索可用；立创开放平台 open.jlc.com 提供官方商品/价格/物流 API，接入需在控制台注册应用并配置密钥、请求签名与 IP 白名单，接入完成前商城网页作为引用层。

## 驱动纪律（每一条都是别人用真金白银换来的）

1. **返回值不是证据**：每个写操作后用独立读取回读确认（getAll / getNetlist / DRC / 截图）；incomplete 不能当 PASS。
2. 批量操作每批 20-25 个器件；DRC/网表查询前等 5-10 秒，save 后等 8-10 秒。
3. 引脚映射：建库时逐脚校验；引脚坐标只从已放置实例读回，绝不信库文档（库 y 轴与画布相反的坑会镜像元件）。
4. 同名多脚网络逐脚验证；NC 与缺失分开记录。
5. 决策日志：G0 的选型、布局取舍、布线策略每条 append；修订用 supersede，不改写历史。
6. 平台陷阱清单见 `references/pitfalls.md`——动手前过一遍。
7. **布局判定三层纪律**：①**丝印范围层**——任何器件丝印所围成范围内不得出现其他任何丝印划定的范围；位号文本=丝印（L3 Attribute 原语、自带绝对坐标、modify 组件不跟随），落位后必须**文本归位**（pcb_text_place.py）——**位号文本不得落在自身器件的丝印划定范围内**（含 XIAO 类模块的天线/USB 舌片那一段丝印），文本与器件之间按"文本盒不与**该件**丝印轮廓相交"判定（他件同理），且**不压任何焊盘（含自身焊盘）**；**搜索序 = 先排除自身丝印禁区，再在四周候选中选**（上/下/左/右→四对角 × 步长 0.3/0.5/0.8/1.2/1.8/2.6mm × 字号 45/30/20mil × 横排/竖排），**「中」候选与任何与自身丝印相交的候选直接剔除**（"中"=器件本体中心，必落在自身丝印轮廓内）；文本盒压他件焊盘/丝印=违纪；②**焊盘真实位置层**——焊盘矩形按自转角 prot 旋出真实几何、局部系统一管线（pcb_bodies_lib），pad×pad/焊盘×他件丝印独立复核，不因丝印存在而免检。丝印与焊盘失位的封装=库缺陷报提问单（X2 案例），不得静默采信。③**丝印间隙层（"器件之间要保持适当间隙"，两层纪律之外的硬指标）**——覆盖区 = **丝印层(L3) ∪ 焊盘** 联合包围盒；**两档间隙都要做并落盘**：`gap0`（丝印范围零覆盖）**= 0 对**（硬指标，不合格即整改）；`gap0.5`（覆盖区各边外扩 0.25mm 的装配间隙口径）**不得互相覆盖、且不得零深度相切**（必须给真实间隙，零深度相切不算合格）。**间隙不足时的挪件顺序**（不许直接放行）：自由件 → 派生小件（保去耦距离 ≤2mm 等硬约束）→ **不动**大件/连接器/板框；工艺冲突挪件（工艺/制造冲突）自主执行并记日志，**其余越界挪件停下上报**。三个易错点：封装丝印的 **ARC 圆弧段**按圆弧解析不得按点对直连（否则虚增丝印盒造出假缺陷）；**焊盘 prot 与 layer 必须进 dump**；**文本层违纪按 gap0 口径判**（gap0.5 外扩环下的穿邻件是噪声）——**但"文本 vs 自身丝印"是独立硬指标，任何口径都不得豁免**（位号就贴在本体上时它与自身丝印必然"重叠"，若把文本整体排除出 gap0 统计就会连带赦免这条缺陷；实现见 `pcb_overlap_check.py` 的 `文本×自身丝印范围`/`文本×自身焊盘` 条目）。

8. **布线优先用平台原生路由器**：每网先走 `pcb_Document.autoRouting`（同步 beta 版；作业模型 `startAutoRouting/getAutoJobStatus/getAutoJobLog/cancelAutoJob` 在当前客户端版本全为非功能存根，不可作备选分支）。自研求解器只在原生路由器"在正确调用方式下连续失败 ≥3 次"后才允许立项，且其产物必须自带 45° 倒角整改。批量 >4 网易过载返 null → 逐网/≤4 网成批 + 冷却 55s。
9. **布线产物三闸门（不过不得进验收）**：①**几何质量门**——全板拐角角度直方图，90° 拐角占比 ≤5%（理想 45° 斜线），落 `reports/_s4e_corner_hist.json`；②**电气门**——线宽符合网级规则（路由器无视网级宽度，必须独立覆写并跑 DRC 增量核查），硬约束网（晶振包地/单层/总长/去耦距离）逐条复核；③**连通门**——几何口径（union-find：段端/焊盘矩形/过孔/T 搭）逐网 `disconnected_members` 为空。`pcb_Net` 长度只作第二口径，**不得作"已布"判据**。
10. **路由结果三态判读**：返回值对象含 `success` 字段 = 引擎跑过（再看 `successNetsCount`/`failedNets`）；返回 `undefined` = 引擎静默失效（批量删线后需 closeDocument→openDocument→activateDocument 复位再重试一次）；画布零产物但有 `failedNets` = 真实不可解。禁止把三者混为一谈（混用会引发无谓重试风暴并误报不可解网）。
11. **"半连通"必须用几何口径发现**：路由器报 success 仍可能留下未连接的焊盘（细间距封装尤其常见）。每网完成后必须跑几何连通表并把 `disconnected_members` 逐张列出；对"路由器漏连的焊盘"采用**硬网+阻塞网成组联合重布**（把阻塞该焊盘的网与该网放进同一次 autoRouting 调用联合规划），单网重试无效时优先用成组联合而非重复单网重试。
12. **布局朝向可布性闸门（"翻转一下就好布"必须变成流程保证，而不是靠眼力）**：器件朝向（rot/mirror）**不进 IR、不进网表、也不进丝印间隙判定**，却直接决定"布不布得出来"——目视发现"某件换朝向可大幅降低布线难度"是常态（模块类大件与连接器尤其如此）。因此布局阶段必须把朝向做成**闸门**而非静态约束条文：**①枚举有意义的朝向候选**（旋转安全；**镜像仅限无极性件**——LED 阳/阴极不对称，镜像即电气错误）→ **②代理评分**（每网最小生成树总长、异网直线段交叉数、跨板惩罚、关键链总长与直线性、走廊占用率）→ **③硬可达性闸门**（用 A\* 求解器或原生路由器对关键网做可达性预检，不可达即淘汰该候选并记不可达网与阻塞源坐标）→ **④择优落位**（只重落差异件，其余零漂移）→ **⑤重跑几何复检**。**红线**：丝印间隙、去耦距离、插拔方向、禁布区、板边距是硬门，评分只在合格布局之间排序。候选表与评分明细必须落盘。

13. **阶段交付前 error/warning 必须清零（"报错不能带着过门"）**（2026-10-22 委托方指示，flexiheal-v2 固化）：**执行子 session 在提交 final 汇报之前，必须先把自己这一阶段产生的 error 与 warning 全部清零**——ERC / DRC / 断言 / 几何检查 / 脚本日志里的每一条都要逐条过，**不许把"我已解释"当作"已解决"**。具体动作：①**列全**（把该阶段的每一条 error/warning 连同规则名、涉及对象、复现读数落盘到 `reports/`）；②**能修的当场修**（改完必须**复测**并给出修前修后对照，不接受"应该好了"）；③**确实修不掉的，写正式豁免记录**（`reports/waivers_*.md`：根因 + 影响评估 + 为什么不修 + 后续动作 + 谁裁决），**主 session 裁决后才算过门**；④**汇报里必须显式写出清零账**（error 0 / warning 0 或豁免 N 条），**禁止报"完成"却把 warning 藏在附注里**。**已知平台级不可消除项（举例）**：原理图**无 NC 原语 API**（`sch_Primitive*` 无 NoConnect 类）→ 模块未用脚的浮空脚 warning 消不掉，验收口径是"ERC 悬空脚集合 == 画布 ✕ 标注集合，双向差集为空"；**器件属性偏离库器件**（`ATTRMATCHCODE`）→ 用"泛用件 + 自定义 Name/值"必然触发，平台无 `sch_PrimitiveAttribute.create`（**属性原语只能 get/modify/delete**）、`sch_PrimitiveComponent.modify({component:...})` **改不动设备绑定**，因此**除非改选真实料号件重新落位**，否则只能走豁免。**注意豁免不等于忽略**：豁免必须写清"对本板功能有无影响"，有影响的一律升级为设计变更项上报。

14. **工程与页面只走嘉立创官方 API 打开，查 API 只走官方文档命令**（2026-10-22 flexiheal-v2 实测固化）：①**打开工程/页面的唯一合法路径** = 官方 API 三连：`eda.dmt_Project.openProject(projectUuid)` → `eda.dmt_EditorControl.openDocument(pageUuid)` → `eda.dmt_EditorControl.activateDocument(pageUuid@projectUuid)`；**禁止** `lceda-pro open --path <本地工程文件或目录>`（`.eprj/.eprj2/.eprj3/.elib`）——**全在线模式下客户端会弹模态框"客户端全在线模式下不支持打开 .eprj 和 .epj2 工程文件，请在离线模式或全离线模式打开"**，该模态框**会卡住 GUI 渲染进程、让该会话的全部 invoke 挂起**；而且它打开的是**另一份副本**，与活体会话脱节（这正是"工程 zip 与编辑器内存态不一致"的一个来源）。确需打开本地工程文件 → **必须先由人工把客户端切到离线模式**，并在决策日志记录。②**禁止靠猜方法名调 API**：任何"这个 API 叫什么/参数怎么传"的疑问，一律先查官方参考命令 `lceda-pro doc api`（渐进式：`--class-name X` → `--method-name Y`），它直接给出**类名、全部方法、参数签名、官方示例代码**（例：`eda.pcb_ManufactureData` 下 `getGerberFile(fileName?, colorSilkscreen?, unit?, digitalFormat?, other?)`、`getPickAndPlaceFile`、`getBomFile`、`getIpcD356AFile`、`getIpc2581CFile`、`getNetlistFile`、`get3DFile`、`getManufactureData`（**仅私有化部署有效，其它版本 throw**））——这条能省掉整轮"试探式试错"。③**出现模态提示框 = 该会话已卡死**：用 `lceda-pro session list` 定位对应 session，`lceda-pro session close`（必要时 `session abort`）关掉后换别的会话，**不要在卡死的会话上反复重试**。④**同一张原理图页只能被一个 EDA 会话持有**：别的会话 `openDocument` 会返回 tabId 但**不生成页签**（表现为"原理图打不开"+ `SCH_DrcUtil: doctype(3) not support check sch drc`），必须用 `lceda-pro session list` + 逐会话 `getSplitScreenTree()` 找到真正持有它的那个会话（pitfalls #101）。⑤**打开后必须回读确认**：`getSplitScreenTree()` 看页签是否真的生成、`getAllPrimitiveId()` 看内容是否可读，**不接受"API 返回了 tabId"就算打开成功**。

15. **过孔↔焊盘净距纪律（"过孔不要紧挨着焊盘"）**（2026-10-22 委托方指示，flexiheal-v2 固化）：**via-in-pad 只堵住了最坏的一种情况，"过孔紧贴焊盘"同样是制造缺陷**：① 手焊/回流时焊锡沿铜面被**吸进过孔孔洞**（吸锡/wicking），焊点发虚、虚焊；② 过孔铜盘挤占焊盘的可上锡面积，0603 这类小焊盘尤其致命；③ **同网相邻不报 DRC**（异网才走 clearance 规则）→ **不会自己暴露**，必须独立体检。**判据（全部确定性，不许凭感觉）**：**重叠 = 过孔铜盘与焊盘铜面相交**（**不是"过孔圆心落在焊盘内"**——后者会同时漏判与误判：漏判"圆心在焊盘外但铜盘压进焊盘"，误判"椭圆焊盘按 AABB 判"）；**异网**铜面净距 ≥ 0.254mm；**同网**取**孔边**（孔壁）到焊盘铜面的净距 ≥ **0.35mm**（0.5mm 为推荐档，几何不可达时按 0.35mm 收口并写豁免，**不许为凑间距去动已验收的器件位置**）。**焊盘真实几何口径**：本地 w/h 按**焊盘自转角 prot** 旋出的矩形；椭圆按等效半径（**不可用外接矩形近似**）。**整改顺序**：① **同轴外推**（沿走线方向把过孔往外推，走线段随之延长——不动他网、不动器件、拓扑不变）；② 自由搬迁（仅限无主干的缝合孔，且搬迁后须仍在同网铺铜内）；③ 都不行 → 写豁免记录，**不得挪器件**。**工具**：`scripts/eda/pcb_via_pad_clearance.py`（体检，须产出独立 JSON 证据）+ `scripts/eda/` 下的求解脚本（出可整改方案）。**注意判据本身也要审**：判据写错会同时造成漏判与误判，改判据必须用独立方法交叉验证（如旋转矩形四角 + 点在凸多边形内判定），并给出全样本最大偏差。**求解器也要被验收**：整改方案的落点评估必须是**完整 DRC 口径的子集**（走线/焊盘/过孔/孔洞/板边/铺铜），且**过孔是通孔**——与走线/焊盘的距离**必须扣掉过孔铜盘半径**，只扣走线半宽会系统性高估 0.3mm；**同网过孔之间也要查孔壁间距**（同网铜面可重叠，但两孔重叠 = `Hole to Hole` 违例，DRC 按孔判不按铜面判）。方案生成后**必须冷重启跑真实 DRC 复核**，不得以自查通过代替。

16. **布局分区纪律**（2026-10-23 委托方指示）：布局按"先粗后精"推进。第一步做分区粗摆：依据原理图的功能分区，确定各功能区在板上的大致位置；同一功能的器件放在一起，芯片与其外围器件放在一起；原理图上相连器件的摆放服从分区结构，避免飞线式见缝插针。第二步在分区合格的前提下精摆。主电路连线尽量短，线宽尽量宽；粗摆时为主电路预留走廊，稠密区保留主电路走廊宽度。`scripts/eda/pcb_partition_check.py` 提供量化自检（分区覆盖/分区结构/芯片-外围簇/主电路 MST），供精摆与验收时选用来量化分区质量，结果落 `reports/`。

17. **走线形态纪律**（2026-10-23 委托方指示）：走线尽量短，避免兜圈子；使用钝角走线，避免锐角与直角走线。`scripts/eda/trace_quality_check.py` 提供量化自检（真实内角直方图与每网实际长度对最小生成树长度之比），供布线验收时选用来定位可疑网段，结果落 `reports/`。

## 复用优先原则

- 优先从 `blocks/` 取 verified 状态的电路块（含固定拓扑、边界端口、布局约束、验证判据）；
- 新建块必须声明来源证据（datasheet 章节号 / 参考设计 / 有验证记录的开源工程），状态标记 draft；
- "Reuse before rewriting"：每次重写都要把原方案付过的代价重付一遍。

## 与验证层的接口

- G2/G5/G6 用的断言文件由 `ir2assert.py` 在 G1 门自动生成：每个 IR 网络 → `net_members`（op "==" 精确成员集）——意外短路=多成员、漏连=缺成员，两类缺陷都 FAIL；`must_connect` 在短路时天然 PASS，不作为短路证据（语义决策 2026-10-19）；
- 无 SPICE 模型的商用芯片：分立级仿真（`testbench_run.py`）+ datasheet 计算复核，结果标 COMPUTED；**禁止伪造厂商模型**（pcbskill/salitronic 双重教训）。
