# 提问策略：四类信息 × 问题测试（依据 Ask Early, Ask Late, Ask Right + pcb-skill 实践）

## 为什么提问策略必须外置

文献结论（arXiv:2605.07937）：现有模型没有一个天然落在最优提问窗口内——有的过度提问（单会话成功率反而最低），有的从不提问。且"拖到中点之后才澄清，比从不提问更糟"。因此：
- **goal / constraint 类缺口必须在设计开始前锁定**；
- 提问质量 > 提问频率：一次结构化清单 > 连环盘问；
- 本 skill 用"规格完备性检查"（mission_check.py）代替模型直觉判断该不该问。

## 问题测试（判定要不要问）

问自己：**"这个问题的两个答案，会造出两块不同的板子吗？"**

- 会 → 该问（这是真正影响设计的用户决策）；
- 不会 → 不该问（用默认值/行业标准/软约束排序自决，记决策日志）。

### 该问的例子（均为 goal/constraint 类缺口）
- "续航 ≥3 小时是亮屏还是灭屏续航？"（决定电池容量→板尺寸）
- "5V 输出精度 ±3% 是带纹波的综合精度还是直流精度？"（决定纹波预算分配）
- "板框尺寸 40×60mm 是硬上限还是目标值？"（硬约束 H 或软约束 S 的区别）
- "外壳空间是否限制连接器位置？"（布局硬约束）

### 不该问的例子
- "去耦电容取多少？"（行业标准 100nF，context 类）
- "过孔用 24/12mil 可以吗？"（默认规则，constraint 已默认）
- "要不要画原理图？"（流程自含，goal 类已定）

## 首轮提问的结构化清单模板

一次 AskUserQuestion 打包所有 goal/constraint 缺口，常见组：

1. **功能与接口**（goal）：这块板要实现什么？输入输出分别是什么？
2. **电源**（goal+constraint）：供电来源与电压？板上需要的电源轨及电流？
3. **量化指标**（constraint）：精度/纹波/效率/保护阈值等，哪些是硬指标？
4. **形态**（constraint）：尺寸上限？层数期望？安装/接口位置约束？
5. **成本与打样**（constraint+S）：目标成本？打样渠道（默认嘉立创）？数量？
6. **交付物勾选**：BOM？教学讲义（可选）？
7. **授权**：是否常设授权（后续按软约束排序自决）？

每题给推荐默认值（用户可直接采纳），降低回复成本。

## 提问预算

- 首轮：一次打包全部缺口；
- 第二轮：仅允许针对 mission_check FAIL 后剩余缺口；
- 两轮之后仍缺 → 挂起为"待补充"，不许设计。
